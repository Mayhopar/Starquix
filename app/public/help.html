Starquix help

Edit real Astro files on your computer. Keep regular ZIP backups.

Startup · Storage · Editing limits · AI · Recovery

Startup

Starquix runs each project with its own local Astro server. The first open of an imported site may install its packages, which needs the network once.

Storage and backups

Projects are saved by the app on this computer. Export a ZIP regularly as your backup. A project made with the older browser version of Starquix comes in the same way: export it as a ZIP there, then Import it here.

Every change is stored the moment the editor accepts it. There is no separate save step: reloading, closing the window or a preview restart cannot lose an accepted change. The preview and the project files catch up in the background; export and deployment wait for that to finish.

Import and editing limits

  • Import an Astro folder, up to 2,000 files / 500 MB. Visual styling works best with Tailwind CSS.
  • Dependency folders, build output and hidden files (including .env) are skipped. Private registries and server-secret-dependent projects may not run.
  • Preserved source, media and fonts can be exported, but not every imported construct is visually editable. Arbitrary Astro integrations are not guaranteed.
  • Public SEO and database/schema/form-binding controls are hidden where their editor state cannot persist.
  • Group moves containing source elements are refused, even within one file. Move one source element at a time, or edit the original source.
  • Unsupported CMS/MDX expressions, imports and component constructs remain read-only. Edit their original source rather than forcing a visual rewrite. Dynamic routes also have source-based editing/deletion limits.

AI and provider charges

AI is optional. Your provider keys are stored locally. Invoking AI sends prompts/context to your selected provider. Provider charges are separate from Starquix; review provider pricing and limits before use. AI follows the same unsupported SEO/database restrictions.

Recover without deleting your work

Accepted changes are already stored, so recovery never has to save anything first. If a change could not be stored, the control you used says so and keeps your input for another try; earlier changes are unaffected.

Create/import failures keep existing projects; imports retain selected files for retry. No recovery action automatically deletes app data.

“Try again” retries startup or remounts a failed editor. “Reload” is safe: the editor restores your stored changes and resumes writing them to the project files. The preview restarts itself after a transient failure; “Restart preview” is offered only when that did not help.

“Download diagnostics” saves JSON locally with only app version, time, coarse platform family, snapshot version and a stable failure category. It excludes project names/IDs, source/files, URLs, raw errors/stacks, local storage contents, keys/tokens and provider responses. Nothing is uploaded automatically.
